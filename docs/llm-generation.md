# CliProxy 연결과 연구노트 생성

## 설정

1. 백엔드 환경에서 `pip install -r requirements-dev.txt`를 실행하고 서버를 재시작합니다.
   시작 시 연결 설정과 생성 작업용 테이블을 추가합니다. 기존 노트는 변경하지 않습니다.
2. 기관 관리자 계정으로 **플랫폼 연동 → LLM API 연결**에 들어갑니다.
3. CliProxy를 선택하고 서버에서 접근 가능한 Base URL을 입력합니다.
   기본값은 `http://127.0.0.1:8317/v1`입니다. `/chat/completions`는 붙이지 않습니다.
   Docker에서 호스트의 CliProxy에 접근하려면 `http://host.docker.internal:8317/v1` 등의 주소가 필요합니다.
4. CliProxy의 **클라이언트 API 키**를 입력합니다. 관리 API 키나 OAuth 토큰을 입력하는 곳이 아닙니다.
   인증 없는 로컬 CliProxy는 키를 생략할 수 있습니다.
5. **모델 목록 불러오기**에서 반환되는 모델 ID를 선택하거나 직접 입력합니다.
   **생성 연결 테스트**는 해당 모델로 짧은 JSON 초안 1회를 실제 생성합니다.
6. **연결 저장**을 누릅니다. 기존 편집기의 AI 초안과 대량 생성이 같은 기관 설정을 사용합니다.
   CliProxy의 JSON 모드는 기본적으로 끄고, 해당 모델이 `response_format`을 지원할 때 켜세요.

OpenAI와 다른 OpenAI 호환 서버도 같은 화면에서 설정합니다. `/models` 목록 조회가
없는 서버에서는 모델 ID를 직접 입력하고 생성 연결 테스트를 이용할 수 있습니다.
연결 설정은 기관별로 분리되며 해당 기관 관리자만 변경하거나 테스트할 수 있습니다.
개인 연구자는 자신의 프로젝트에서 설정된 연결을 이용할 수 있습니다.

## 입력과 결과

프로젝트 → 연구노트 → **AI 대량 생성**에서 다음을 입력합니다.

- 각 노트: 제목, 작성일(YYYY-MM-DD), 실제 수행 내용·조건·측정값 등 작업 메모.
- 선택 자료: 같은 프로젝트의 기존 노트 본문과 첨부 이미지/PDF 페이지 최대 4장.
  이미지 자료를 선택하면 이미지 입력을 지원하는 모델을 사용해야 합니다.
- 공통 배경: 연구 목표, 용어, 장비 등. 이것만으로 노트를 생성하지 않으며 각 항목에 근거 자료가 필요합니다.
- 언어: 한국어 또는 영어. 회사에서 설정한 노트 포맷의 섹션을 따릅니다.

CSV 양식 다운로드를 사용할 수 있습니다. UTF-8 CSV의 헤더는 `title,written_date,memo`
또는 `제목,작성일,메모`입니다. 쉼표나 줄바꿈이 포함된 셀은 큰따옴표로 감싸고,
셀 내부의 큰따옴표는 두 번 씁니다. CSV는 최대 2MB, 항목은 1~100개입니다.

```csv
title,written_date,memo
센서 측정,2026-11-17,"출력값 10.1, 10.2, 10.1을 기록함. 동일 조건 3회 반복."
재측정 준비,2026-11-18,샘플 B 재측정을 위한 장비 세팅 완료. 측정은 아직 수행하지 않음.
```

결과는 모두 **초안**이며 제목·작성일·본문·편집 문서와 첫 리비전을 저장합니다.
입력에 없는 결과는 만들어내지 않고 `[확인 필요]`로 표시하도록 지시합니다.
생성 결과를 검토·수정한 뒤 기존 제출/승인 흐름을 이용하세요.

창을 닫아도 작업은 서버에서 계속됩니다. 다시 대량 생성 창을 열어 최근 20개 작업을
확인할 수 있습니다. 취소는 진행 중인 API 응답을 기다린 후 결과를 저장하지 않고,
남은 항목을 취소합니다. 실패·취소 항목만 재시도하며 성공한 노트는 유지됩니다.
원본 입력과 참조 노트 ID는 작업 기록에 보관하고, 생성 모델과 작업 ID는 문서 리비전에 남깁니다.

## 운영

- 현재 내장 작업 실행기는 **단일 API 프로세스**용입니다. `uvicorn app.main:app --workers 1`
  로 실행하세요. 복수 워커/복수 인스턴스 운영에는 외부 작업 큐가 필요합니다.
- 최대 2개 작업을 동시에 처리하며, 각 작업의 노트는 순차 생성합니다. 전체 활성 작업은 최대 20개입니다.
- 서버 재시작 시 중단된 항목을 실패로 표시합니다. 성공 결과는 보존하며 화면에서 재시도합니다.
- 중복 요청은 사용자와 `request_id`로 구별합니다. 노트·편집 문서·완료 상태는 한 DB 트랜잭션으로 저장합니다.
- API 키는 Fernet으로 암호화하여 DB에 저장하고 API 응답에 반환하지 않습니다.
  `LLM_ENCRYPTION_KEY` 또는 자동 생성된 `backend/.llm-encryption.key`를 안전하게 백업하세요.
  해당 키 파일은 정적 `/storage` 경로 밖에 있으며 Git에서 제외합니다.
  컨테이너를 재생성하는 환경에서는 고정된 `LLM_ENCRYPTION_KEY`를 환경 변수로 공급하세요.
- 주소를 바꿀 때 기존 API 키를 새 주소로 자동 전송하지 않습니다. 새 주소에 맞는 키를 다시 입력하세요.
- 기관별 설정이 없으면 기존 `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL` 환경 설정을 사용합니다.
  기관 설정에서 AI 사용을 끄면 환경 설정으로 자동 복귀하지 않습니다.
- 실제 CliProxy 서버 주소, 키, 계정과 모델은 사용자가 준비해야 합니다. 모의 서버 테스트는 실제 모델의 품질이나 사용 한도를 검증하지 않습니다.

## API

모든 경로에 LabNote 로그인 Bearer 토큰이 필요합니다.

| 경로 | 용도 |
| --- | --- |
| `GET /llm/connection` | 소속 기관 설정 조회. `company_id` 선택 가능 |
| `PUT /llm/connection` | 기관 설정 저장. 키 생략은 같은 주소의 기존 키 유지 |
| `POST /llm/models` | 입력한 연결 설정으로 모델 목록 조회 |
| `POST /llm/test` | 선택 모델에 실제 생성 테스트 |
| `POST /llm/batches` | 생성 작업 등록(202 응답) |
| `GET /llm/batches?project_id=...` | 프로젝트 작업 내역 |
| `GET /llm/batches/{id}` | 항목별 상태·오류·결과 노트 ID |
| `POST /llm/batches/{id}/cancel` | 남은 작업 취소 |
| `POST /llm/batches/{id}/retry` | 실패·취소 항목 재시도 |

공식 호환 규격 참고: [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI),
[OpenAI Python SDK](https://developers.openai.com/api/reference/python).
